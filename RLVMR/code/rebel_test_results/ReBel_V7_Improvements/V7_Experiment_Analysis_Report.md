> **核心问题**: 为什么40-50 epoch后模型成功率无法突破85-90%？

## 1. 执行摘要

### 1.1 实验概述

V7版本在V6基础上针对三个核心问题进行了改进：
1. **熵坍塌** → 引入Clip-Cov熵保护机制
2. **clip限制** → 放宽clip_ratio上限至0.28
3. **样本不平衡** → 维持KL in Loss配置保护少数任务

### 1.2 实验配置

| 参数 | V7-Exp1配置 |
|------|-------------|
| KL方式 | KL in Loss (kl_loss_coef=0.01) |
| Clip-Cov | 启用 (lb=0.0, ub=0.5) |
| clip_ratio | [0.2, 0.28] |
| entropy_coeff | 0.001 |
| min_samples_ratio | 0.15 |
| 训练轮数 | 100 epochs |

### 1.3 关键发现

| 指标 | V6-Exp2 (基线) | V6-Exp3 | V7-Exp1 | 目标 |
|------|---------------|---------|---------|------|
| **最终成功率** | 78.1% | 84.4% | **82.4%±4.3%** | 90% |
| **最高成功率** | 78.1% | 84.4% | **87.5%** | 90% |
| look_at最终 | 83.3% | 16.7% | **67.6%±12.5%** | >75% |
| pick_two最终 | 56.5% | 87.0% | **81.7%±6.3%** | >80% |

**结论**: V7未能达到90%的目标成功率，核心瓶颈是**look_at任务的极端不稳定性**。

## 3. 核心问题分析

### 3.1 问题一：look_at任务极端不稳定

**数据证据**：
```
look_at任务稳定性分析 (60-100 epoch):
  平均成功率: 59.9%
  标准差: 12.5% (所有任务中最高)
  最大波动: 52.5% (epoch 80: 77.8% → 30.8%)
  平均相邻epoch变化: 20.4%

对比其他任务:
  pick_and_place: 97.8% ± 1.6%
  pick_heat: 95.5% ± 3.3%
  pick_two: 81.7% ± 6.3%
  pick_clean: 77.4% ± 4.8%
  pick_cool: 72.3% ± 1.7%
```

**根因分析**：

1. **样本数量极度不平衡**
   - look_at任务在训练数据中占比约13%（最少）
   - 每轮训练仅约10-20个样本，统计显著性不足
   - 梯度信号噪声大，更新方向不稳定

2. **任务特殊性**
   - look_at需要复杂的多步骤决策：找物品→找灯→开灯→检查
   - `has_state_change`始终为false，信念分组粒度粗糙
   - 与其他pick_*任务的策略差异大

3. **评估集偏差**
   - 128个验证样本中look_at数量有限（约12-18个）
   - 单个样本变化导致成功率大幅波动（±5-10%）

### 3.2 问题二：任务间梯度竞争与马太效应

**现象描述**：

```
任务成功率分布 (后期平均):
  ┌─────────────────────────────────────────────┐
  │ pick_and_place  ████████████████████ 97.8%  │ ← 接近饱和
  │ pick_heat       ███████████████████  95.5%  │ ← 接近饱和
  │ pick_two        ████████████████     81.7%  │
  │ pick_clean      ███████████████      77.4%  │
  │ pick_cool       ██████████████       72.3%  │
  │ look_at         █████████████        67.6%  │ ← 瓶颈任务
  └─────────────────────────────────────────────┘
```

**问题机制**：

1. **饱和任务梯度消失**
   - pick_and_place、pick_heat已达95%+，优势值接近0
   - 几乎不再提供有效梯度信号
   - 但仍占用大量训练样本（约35%）

2. **少数任务梯度被淹没**
   - look_at样本少（13%）但方差大
   - 单个batch中look_at梯度可能被多数任务梯度抵消
   - per_task_normalization虽然启用，但无法解决批次间不平衡

3. **马太效应**
   - 高成功率任务继续被强化（更多正样本）
   - 低成功率任务持续随机漂移
   - 任务间差距扩大

### 3.3 问题三：Clip-Cov熵保护的"副作用"

**数据证据**：

```
熵变化趋势:
  早期 (0-10 epoch): 0.341
  后期 (50-60 epoch): 0.436
  继续训练 (60-100): 0.463
  变化: +28% (熵上升而非下降)
```

**分析**：

Clip-Cov机制成功防止了熵坍塌，但带来新问题：

1. **过度探索**
   - 熵持续上升意味着策略更加不确定
   - 对于已经高成功率的任务，这种探索是浪费
   - 探索没有针对性，不是针对look_at等难任务

2. **clip_cov_ub=0.5的影响**
   - 允许50%的样本被clip保护
   - 可能阻止了对高性能任务的进一步稳定化

### 3.4 问题四：验证集噪声与评估不稳定

**计算分析**：

```
假设look_at验证样本数 = 12
单样本影响 = 1/12 ≈ 8.3%

观察到的look_at成功率变化:
  epoch 75: 83.3%
  epoch 80: 30.8%
  变化: -52.5%

可能的解释:
  如果12个样本中，有6-7个样本的结果不同，
  就会导致50%+的成功率变化
```

**问题根源**：
- 验证集对少数任务的统计显著性不足
- 评估噪声掩盖了真实的训练进展

### 4.3 数学分析：训练停滞的边界条件

设任务集合 $T = \{t_1, t_2, ..., t_n\}$，各任务成功率 $s_i$，样本数 $n_i$。

**整体成功率**：
$$S = \sum_{i=1}^{n} w_i \cdot s_i, \quad w_i = \frac{n_i}{\sum_j n_j}$$

**当前状态** (V7 epoch 100)：
```
t1 (pick_and_place): s1=0.978, w1=0.20
t2 (pick_heat):      s2=0.955, w2=0.17
t3 (pick_two):       s3=0.817, w3=0.15
t4 (pick_clean):     s4=0.774, w4=0.18
t5 (pick_cool):      s5=0.723, w5=0.17
t6 (look_at):        s6=0.676, w6=0.13

S = 0.978×0.20 + 0.955×0.17 + 0.817×0.15 + 0.774×0.18 + 0.723×0.17 + 0.676×0.13
  ≈ 0.833 (83.3%)
```

**要达到90%的目标**：

假设t1-t5维持当前水平（已接近上限），则look_at需要：
$$0.9 = 0.871 × 0.87 + s_6 × 0.13$$
$$s_6 = \frac{0.9 - 0.757}{0.13} = 1.10$$

**结论**：仅优化look_at无法达到90%目标，需要同时提升多个任务。

## 5. 解决方案

### 5.1 短期方案：任务自适应采样与加权

**方案5.1.1: 动态任务采样权重**

```python
# 根据任务成功率动态调整采样权重
def compute_task_weights(task_success_rates, alpha=2.0):
    """
    低成功率任务获得更高采样权重
    alpha: 控制权重差异程度
    """
    weights = {}
    for task, sr in task_success_rates.items():
        # 反向加权：成功率越低，权重越高
        weights[task] = (1 - sr) ** alpha

    # 归一化
    total = sum(weights.values())
    return {k: v/total for k, v in weights.items()}
```

**预期效果**：
- look_at任务样本数增加约2-3倍
- 梯度信号统计显著性提升
- 缓解马太效应

**方案5.1.2: 任务级梯度缩放**

```python
# 对不同任务的梯度进行缩放
def scale_task_gradients(gradients, task_labels, task_weights):
    """
    根据任务重要性缩放梯度
    """
    scaled_grads = []
    for grad, task in zip(gradients, task_labels):
        scale = task_weights.get(task, 1.0)
        scaled_grads.append(grad * scale)
    return scaled_grads
```

### 5.2 中期方案：分阶段训练策略

**Phase 1: 全任务预训练 (0-30 epoch)**
- 目标：所有任务达到基础水平（>50%）
- 配置：标准配置，均匀采样

**Phase 2: 难任务强化 (30-60 epoch)**
- 目标：提升look_at、pick_cool等瓶颈任务
- 配置：
  - look_at采样权重 ×3
  - 降低已饱和任务(pick_and_place)的学习率
  - 增大entropy_coeff到0.005

**Phase 3: 平衡微调 (60-100 epoch)**
- 目标：稳定所有任务性能
- 配置：
  - 恢复均匀采样
  - 降低学习率至1e-7
  - 启用任务级早停

### 5.3 长期方案：算法层面改进

**方案5.3.1: 任务条件策略网络**

```
当前: π(a|s, task) 共享所有参数
改进: π(a|s, task) = π_shared(a|s) + π_task(a|s, task)

task-specific head可以学习任务特有的策略偏置
```

**方案5.3.2: 分层强化学习**

```
高层策略: 选择子目标 (find object, find lamp, use lamp, examine)
低层策略: 执行具体动作

对于look_at任务，高层策略可以显式编码任务流程
```

**方案5.3.3: 课程学习**

```
难度估计: difficulty(task) = f(success_rate, variance, complexity)

训练顺序:
  1. 先训练简单任务到高水平
  2. 逐步引入难任务
  3. 使用知识蒸馏从简单任务迁移
```

## 6. 实验结论

### 6.1 核心发现总结

1. **成功率停滞的本质原因**：不是熵坍塌或clip限制，而是**任务间样本不平衡导致的优化不均衡**

2. **V7改进的实际效果**：
   - Clip-Cov成功阻止熵坍塌（熵上升28%）
   - 但未能解决look_at任务的极端不稳定性（波动达52.5%）
   - 最高成功率87.5%，未达90%目标

3. **瓶颈任务识别**：
   - look_at: 成功率67.6%±12.5%，需优先提升
   - pick_cool: 成功率72.3%±1.7%，稳定但偏低
   - pick_clean: 成功率77.4%±4.8%，有提升空间

### 6.2 后续实验优先级

| 优先级 | 方案 | 预期提升 | 实现难度 |
|--------|------|---------|----------|
| P0 | 任务自适应采样 | +5-8% | 低 |
| P1 | 梯度缩放 | +3-5% | 低 |
| P2 | 分阶段训练 | +5-10% | 中 |
| P3 | 任务条件策略网络 | +10-15% | 高 |

### 6.3 预期目标

通过实施P0+P1方案：
- 整体成功率：82.4% → 90%+
- look_at成功率：67.6% → 80%+
- pick_cool成功率：72.3% → 85%+
