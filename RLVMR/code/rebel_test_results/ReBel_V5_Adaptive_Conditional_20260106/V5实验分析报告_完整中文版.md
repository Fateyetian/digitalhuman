### 3.2 问题二：归一化策略 (Normalization Strategy) 失效

#### 3.2.1 条件归一化阈值过低

当前V5配置：
```yaml

min_std_for_norm: 0.1         # 阈值太低
```

从日志观察：`adv_std_look_at_in_light = 1.000`（始终为1.0），说明：
- per_task_normalization 强制将 std 归一化为 1
- conditional_norm 逻辑**未按预期触发**（样本数 > 10，std > 0.1）
- 对小样本任务产生了**噪声放大**

#### 3.2.2 问题证据

```python

if sample_count < min_samples_for_norm:  # look_at 有 35 个样本，不触发
    # 使用全局统计量（保护性归一化）
elif std < min_std_for_norm:  # std 通常 > 0.1，不触发
    # 保守归一化
else:
    # 标准归一化 -> look_at 走这条路径，但这不合适！
    normalized_adv = (task_adv - mean) / (std + epsilon)
```

look_at 任务有 35 个训练样本（占 13%），样本数虽大于阈值 10，但**相对于其他任务仍然偏少**。应该使用**相对阈值**而非绝对阈值。

### 3.3 问题三：KL 散度控制策略不当

#### 3.3.1 当前配置分析

当前V5实验使用：
```yaml
actor_rollout_ref.actor.use_kl_loss: True
actor_rollout_ref.actor.kl_loss_coef: 0.01
actor_rollout_ref.actor.kl_loss_type: low_var_kl
algorithm.use_kl_in_reward: False  # 关键：未启用！
```

**问题**：将 KL 惩罚直接加入 Loss 函数，而非加入 Reward

这种做法的缺陷：
1. KL 惩罚的梯度直接影响所有参数，可能导致训练不稳定
2. 无法与 Advantage 归一化协同工作
3. 对于小样本任务，KL 约束可能过强或过弱

#### 3.3.2 推荐配置：K1 Estimator in Reward

**最佳实践**：使用朴素 KL 估计器（K1），并将其作为惩罚项加到 Reward 中

公式：在计算 Advantage 时，对每个 token 的奖励 $r_t$ 进行修正：

$$r_t = s_t - \beta \cdot \text{sg}\left[\log \frac{\pi_\theta(y_t | x, y_{<t})}{\pi_{\text{ref}}(y_t | x, y_{<t})}\right]$$

其中 $\text{sg}$ 表示 stop-gradient。

**VeRL 配置**：
```yaml
algorithm.use_kl_in_reward: True   # 启用！
algorithm.kl_penalty: "kl"          # 使用 K1 估计器
algorithm.kl_ctrl.type: "fixed"
algorithm.kl_ctrl.kl_coef: 0.001    # 调低系数
actor_rollout_ref.actor.use_kl_loss: False  # 关闭 Loss 中的 KL
```

**优势**：
1. KL 惩罚通过 Advantage 影响策略，更平滑
2. 与 per_task_normalization 协同：每个任务的 KL 惩罚被独立归一化
3. 避免对小样本任务的过度惩罚

## 4. 分组策略的数学分析

### 4.1 当前分组公式

设 $G_k = \{i : h(b_i) = k, \text{uid}_i = u, \tau_i = t\}$ 为信念分组，其中：
- $h(b)$ = 信念哈希函数
- $u$ = prompt uid
- $t$ = 任务类型

优势归一化公式：
$$\hat{A}_i = \frac{A_i - \mu_{G_k}}{\sigma_{G_k} + \epsilon}$$

### 4.2 问题：小分组中的方差塌缩

当 $|G_k|$ 较小且样本同质时：
- $\sigma_{G_k} \to 0$
- $\hat{A}_i \to \infty$（数值不稳定）
- 强制 $\sigma = 1$ 会引入人工噪声

### 4.3 理论最优分组条件

有效对比学习要求分组满足：

1. **充足样本数**: $|G_k| \geq N_{min}$（推荐: 5-20）
2. **内部方差**: $\sigma_{G_k} \geq \sigma_{min}$（自然方差）
3. **语义一致性**: 同组样本应处于相似决策点
4. **均衡覆盖**: 每个任务应有足够的分组表示

# 优先级顺序很重要 - 先检查 'find' 再检查 'use'
def get_stage_type(subgoal: str) -> str:
    subgoal = subgoal.lower()

    # 优先级1: 完成状态
    if any(x in subgoal for x in ['complete', 'done', 'finished']):
        return 'complete'

    # 优先级2: 搜索阶段（优先于其他）
    if any(x in subgoal for x in ['find', 'look for', 'search', 'locate']):
        return 'find'

    # 优先级3: 导航阶段
    if any(x in subgoal for x in ['go to', 'goto', 'navigate', 'move to']):
        return 'navigate'

    # 优先级4: 拾取阶段
    if any(x in subgoal for x in ['pick', 'take', 'grab', 'get']):
        return 'pickup'

    # 优先级5: 放置阶段
    if any(x in subgoal for x in ['put', 'place', 'drop']):
        return 'place'

    # 优先级6: 使用阶段（放在后面，避免误匹配 'lamp' 等词）
    if any(x in subgoal for x in ['turn on', 'use', 'toggle', 'examine']):
        return 'use'

    # 优先级7: 状态改变阶段
    if any(x in subgoal for x in ['heat', 'cook', 'warm', 'microwave']):
        return 'heat'
    elif any(x in subgoal for x in ['cool', 'chill', 'fridge', 'refrigerat']):
        return 'cool'
    elif any(x in subgoal for x in ['clean', 'wash', 'rinse', 'sink']):
        return 'clean'

    return 'other'

```python
def normalize_advantages_per_task_v6(
    advantages: torch.Tensor,
    task_types: np.ndarray,
    eos_mask: torch.Tensor,
    epsilon: float = 1e-8,
    min_samples_ratio: float = 0.15,  # 相对阈值：至少占总样本的15%
    min_std_for_norm: float = 0.2,    # 提高到 0.2
) -> torch.Tensor:
    """V6改进: 使用相对阈值保护小样本任务"""
    result = advantages.clone()
    unique_tasks = np.unique(task_types)
    total_samples = len(task_types)

    # 计算全局统计量
    all_valid_mask = eos_mask > 0
    global_mean = advantages[all_valid_mask].mean()
    global_std = advantages[all_valid_mask].std()

    with torch.no_grad():
        for task in unique_tasks:
            mask = np.array([t == task for t in task_types])
            sample_count = mask.sum()
            sample_ratio = sample_count / total_samples

            if sample_count <= 1:
                continue

            task_adv = advantages[mask]
            task_eos = eos_mask[mask]
            valid_mask = task_eos > 0

            if valid_mask.sum() == 0:
                continue

            valid_adv = task_adv[valid_mask]
            mean = valid_adv.mean()
            std = valid_adv.std()

            # V6改进: 使用相对阈值
            if sample_ratio < min_samples_ratio:
                # 小样本任务：使用全局统计量 + 保守缩放
                if global_std > epsilon:
                    # 只做部分归一化，保留任务内部差异
                    normalized_adv = (task_adv - mean) / (global_std + epsilon) * 0.5
                else:
                    normalized_adv = task_adv - mean
                result[mask] = normalized_adv * task_eos

            elif std < min_std_for_norm:
                # 低方差任务：仅去均值
                normalized_adv = task_adv - mean
                result[mask] = normalized_adv * task_eos

            else:
                # 正常任务：标准归一化
                normalized_adv = (task_adv - mean) / (std + epsilon)
                result[mask] = normalized_adv * task_eos

    return result
```

def task_weighted_reward(rewards, task_types, task_weights=None):
    """根据任务难度/样本量调整奖励权重"""

        # 自动计算：样本越少权重越高

def normalize_advantages_per_task_v6(
    advantages: torch.Tensor,
    task_types: np.ndarray,
    eos_mask: torch.Tensor,
    epsilon: float = 1e-8,
    min_samples_ratio: float = 0.15,  # 相对阈值
    min_std_for_norm: float = 0.2,
    use_global_for_minority: bool = True  # V6新增
) -> torch.Tensor:
    """V6改进：使用相对阈值 + 全局统计量保护"""

    result = advantages.clone()
    unique_tasks = np.unique(task_types)
    total_samples = len(task_types)

    # 计算全局统计量
    all_valid_mask = eos_mask > 0
    global_mean = advantages[all_valid_mask].mean()
    global_std = advantages[all_valid_mask].std()

    with torch.no_grad():
        for task in unique_tasks:
            mask = np.array([t == task for t in task_types])
            sample_count = mask.sum()
            sample_ratio = sample_count / total_samples

            if sample_count <= 1:
                continue

            task_adv = advantages[mask]
            task_eos = eos_mask[mask]
            valid_mask = task_eos > 0

            if valid_mask.sum() == 0:
                continue

            valid_adv = task_adv[valid_mask]
            mean = valid_adv.mean()
            std = valid_adv.std()

            # V6策略选择
            if sample_ratio < min_samples_ratio:
                # 小样本任务：使用全局统计量 + 缩放
                if use_global_for_minority and global_std > epsilon:
                    # 混合策略：部分使用任务内统计，部分使用全局
                    blend_factor = sample_ratio / min_samples_ratio  # 0 到 1
                    blended_std = blend_factor * std + (1 - blend_factor) * global_std
                    normalized_adv = (task_adv - mean) / (blended_std + epsilon)
                else:
                    normalized_adv = task_adv - mean
                result[mask] = normalized_adv * task_eos

            elif std < min_std_for_norm:
                # 低方差：仅去均值，不缩放
                normalized_adv = task_adv - mean
                result[mask] = normalized_adv * task_eos

            else:
                # 正常归一化
                normalized_adv = (task_adv - mean) / (std + epsilon)
                result[mask] = normalized_adv * task_eos

   - `r_consistency`：Ground Truth 追踪不完整，正确预测被错误惩罚
   - `r_progress`：缺乏 look_at 任务专用检测，该任务无法获得进度奖励
   - `r_exploration`：验证依赖文本解析质量，有效探索被惩罚
   - 第一轮交互时问题尤其严重：所有三个奖励组件都因 Ground Truth 不足而失效

2. **Stage Type 检测顺序错误**（`core_rebel.py:167`）
   - "find lamp" 被错误分类为 'use' 而非 'find'
   - 导致 look_at 任务的分组缺乏区分度

3. **look_at 任务缺乏 state_change 信号**
   - `has_state_change` 始终为 `false`
   - adaptive 模式对该任务的分组粒度不足

4. **条件归一化阈值设置不当**
   - `min_samples_for_norm=10`：使用绝对阈值，未考虑相对样本比例
   - `min_std_for_norm=0.1`：阈值过低，未有效触发保护逻辑

5. **KL 惩罚加入位置不当**
   - 当前：加入 Loss 函数
   - 推荐：加入 Reward（K1 Estimator in Reward）
